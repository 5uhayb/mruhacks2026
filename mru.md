# MRUHacks 2026 Prep Guide

> MRUHacks is Mount Royal University's (Calgary) annual student hackathon. It's free, but you have to register.
> Past editions ran about 24 hours in early-to-mid October (2023: Oct 13–14, 2024: Oct 5, 2025: Oct 4–5), held in the Riddell Library & Learning Centre.
> **Check [mruhacks.ca](https://www.mruhacks.ca) for this year's dates, schedule, tracks, and prizes.**

## 2. Two Weeks Before

- [ ] Register on mruhacks.ca and confirm your spot
- [ ] Join the Discord and read the rules (team size, can you prep code beforehand, etc.)
- [ ] **Form a team** (3–4 people). Try to cover:
  - Frontend / UI
  - Backend / APIs / database
  - Design + pitch/presentation
  - Wildcard (AI/ML, hardware, data)
- [ ] Look at the sponsor prizes and pick 1–2 you'll target. These usually have less competition than the grand prize.
- [ ] Brainstorm 3–5 rough ideas (see Section 4)

## 3. The Week Before

- [ ] Agree on a tech stack the **whole team** already knows. A hackathon is a bad time to learn a new framework.
- [ ] Set up the dev environment on every laptop:
  - [ ] Git + GitHub account; make a shared repo or org
  - [ ] Node / Python / whatever runtime you're using, already installed
  - [ ] Editor + extensions (VS Code, Prettier, ESLint, etc.)
  - [ ] Any CLIs you need (Vercel, Firebase, Supabase, Docker...)
- [ ] Create accounts and get API keys ahead of time (OpenAI/Anthropic, Google Cloud, MongoDB Atlas, etc.). Some take time to approve.
- [ ] Have a starter template ready **if the rules allow it** (boilerplate only, no project code)
- [ ] Do a 1-hour practice build together to work out the Git workflow

### Suggested quick-start stacks

| Goal | Stack |
|---|---|
| Web app, fastest | Next.js + Tailwind + Supabase/Firebase, deployed on Vercel |
| Python / AI-heavy | FastAPI or Flask + React/Streamlit frontend |
| Mobile | React Native (Expo) or Flutter |
| Quick AI demo | Streamlit or Gradio + an LLM API |
| Hardware | Arduino / Raspberry Pi (check whether the event provides hardware) |

## 4. Picking an Idea

**What makes a strong hackathon idea:**
1. **It solves a real problem** you can explain in one sentence
2. **A working demo is possible in about 18 hours of real coding**
3. **It fits a track or sponsor prize**
4. **It has a "wow" moment** in the demo (live AI output, a map, real-time updates, hardware doing something)

**Idea filter:** for each idea, answer:
- Who is it for?
- What's the one core feature?
- Can we show it working in 2 minutes?
- What's the minimum version (MVP) vs. the stretch goals?

**Idea starters:** student life at MRU (course planning, study groups, campus events), Calgary-specific problems (transit, winter safety, local food), accessibility, sustainability, mental health, finance for students, AI tools for education.

## 6. Game Plan for a ~24h Event

| Time into hack | Goal |
|---|---|
| 0–1h | Lock in the idea. Write the MVP feature list. Split up tasks. |
| 1–2h | Repo set up, skeleton running on everyone's machine, deploy a "hello world" |
| 2–10h | Build the core features. Merge often. |
| ~10h | **Checkpoint:** does the main flow work end to end? Cut scope if not. |
| 10–16h | Finish the MVP, connect frontend and backend, fix major bugs |
| 16–19h | Polish the UI, add one stretch feature *only if the MVP is solid* |
| 19–21h | **Feature freeze.** Record a backup demo video, write the Devpost |
| 21–23h | Make slides, rehearse the pitch 2–3 times |
| 23–24h | Submit early. Don't wait for the last minute. |

**Rules for the team:**
- Commit and push small changes often; pull before you push
- Use branches per feature, or split work by file/folder to avoid merge conflicts
- Hardcoding or mocking anything that isn't core to the demo is fine
- Take turns sleeping (even 2–3 hours helps a lot)
- Ask mentors and sponsors for help. That's what they're there for.

- [ ] Project name + one-line tagline
- [ ] **Inspiration**: why you built it
- [ ] **What it does**
- [ ] **How we built it**: tech stack
- [ ] **Challenges we ran into**
- [ ] **Accomplishments we're proud of**
- [ ] **What we learned**
- [ ] **What's next**
- [ ] GitHub repo link (public, with a README)
- [ ] Demo video (2–3 min) + screenshots
- [ ] Live link if deployed
- [ ] Tagged for every track/sponsor prize you qualify for

---

## 8. The Pitch / Demo (2–5 min)

1. **Hook (15s):** the problem, ideally a relatable story or stat
2. **Solution (15s):** what you built, in one sentence
3. **Live demo (1–2 min):** show the main user flow. Lead with the "wow" moment.
4. **How it works (30s):** tech stack and anything technically impressive
5. **What's next (15s):** impact and future plans

**Tips:**
- Rehearse with a timer
- Have the backup video ready in case the live demo breaks
- Open every tab/app you need beforehand, and zoom in so judges can read the screen
- Every teammate should be able to answer "how does X work?"
- Judges usually score on: **technical difficulty, creativity, usefulness/impact, design, presentation**

---

## 9. Making the Most of It

- Go to the workshops, especially early ones on APIs/tools that sponsors provide
- Talk to sponsors: bring your LinkedIn/GitHub, and have a resume on hand if you're job hunting
- Get to know other teams. Hackathons are great for networking.
- Post your project on LinkedIn afterwards (tag teammates + MRUHacks)
- Finishing and demoing **anything** beats an unfinished ambitious project
